# PetSpace 架构概览

本文只描述 PetSpace 的高层设计，不包含实现代码、接口密钥或部署配置。

## 1. 系统边界

```text
Flutter App
├── 电子宠物与动态房间
├── 空间库与内容缓存
├── Agent 流式会话
├── 计划提案、任务清单与复盘
└── Native Bridge
       ↓
Android Native
├── AppWidget / RemoteViews
├── 桌面序列帧动画
├── AlarmManager 计划调度
└── WorkManager 资源恢复
       ↕
NestJS Service
├── 场景与媒体内容
├── Agent 工具编排
├── 计划与每日复盘
├── 长期记忆
└── 实时消息
       ↓
PostgreSQL / pgvector
```

## 2. 电子宠物与 Widget

Flutter 负责完整的房间体验和交互界面，Android 原生层负责系统桌面 Widget。两端只同步场景、状态、动作包和版本等结构化信息，避免通过平台通道传输大尺寸位图。

Widget 默认展示稳定画面，用户交互时播放短序列帧动作，结束后停留在目标状态。后台资源准备失败时保留静态兜底，避免桌面组件白屏。

## 3. 计划执行闭环

计划由 Agent 或用户手动发起，但都需要经过提案、检查和确认：

```text
用户目标
→ 结构化计划提案
→ 用户修改与确认
→ 系统调度
→ 到点提醒 / 场景切换
→ 用户勾选实际结果
→ 每日复盘
```

提醒送达和场景切换只属于系统事件，不会被自动推断为“用户已经完成任务”。真实执行结果以用户勾选和反馈为准。

## 4. Agent 安全边界

Agent 可以查询空间和计划，也可以生成待确认的计划提案。修改计划、取消计划、写入记忆等持久化操作必须匹配用户本轮明确表达的意图。

执行链同时受到以下限制：

- 单轮模型与工具交互轮数上限；
- 整体执行时间预算；
- 搜索等高成本工具的独立调用预算；
- 请求标识与数据库幂等约束；
- 版本检查和并发写入冲突处理。

## 5. 分层上下文与长期记忆

上下文分为三层：

1. 最近消息原文，用于保持当前对话细节；
2. 当前会话滚动摘要，用于压缩较早对话；
3. 经过用户确认的长期记忆，用于跨会话个性化。

长期记忆通过结构化类型、关键词和向量相似度混合排序。计划时间、任务状态等确定性事实始终查询业务数据库，不以模型摘要或向量召回结果为准。

## 6. 动态内容管线

场景使用 Manifest 描述背景、角色状态、交互热点、动作素材和 Widget 资源。内容工作台负责视频裁剪、动作抽帧、版本校验和发布，客户端负责按版本拉取并缓存最终资源。
